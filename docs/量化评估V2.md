# GoldQuant 系统评估 V2（顶级量化视角·复评）

> 评估日期：2026-07-29
> 评估方式：直接阅读修复后代码（commit `a199dc0` 及工作树），逐一核验 V1 所列 A–G 项是否真落地、实现是否扎实。
> 结论先行：**V1 大部分项已真实落地且实现有水准，但"无已知遗留项"的结论不成立**——基本面因子在历史回测中实际失效、walk-forward 存在边界标签泄漏、MVO 非真正约束优化器。下面区分"真修复 / 残留 / 名不副实"。

---

## 一、真实落地且实现扎实的修复

### D. 权重 OOS 闭环 ✅（V1 最重要项，已正确闭合）
- `scripts/factors/fit_weights.py:25` `fit_walk_forward_weights`：train_window=504（~2 年）、step=63，每个测试日 `td` 仅用 `[td-504, td-1]` 训练，写时变表 `factor_weights_ts.yml`，默认 walk-forward（`--static` 显式才走全样本，且注释"勿用于 live"）。
- `quant/config.py:89` `load_factor_weights(as_of)` 取 `≤as_of` 最近一组；`strict_oos_weights=true`（默认）时**禁止回退静态全样本 yml**——live 无时变表则返回 None → 调用方回退 `registry.weights()`（等权默认），**不会前视**。这条闭环是干净的。
- 证据：`config.py:113` 优先读 ts 表，`strict_oos and as_of → return None` 阻断静态回退。

### C. 组合优化升级 ✅
- `quant/portfolio/mvo.py` 解析 MVO `w = Σ⁻¹(μ/λ)` + 非负 + 单票 cap 迭代投影；`quant/portfolio/ewma.py` RiskMetrics 风格递归协方差（λ=0.94）。
- `quant/portfolio/target.py:171` `optimizer=mvo` 分支接入，`quant.yml:102` 默认 `optimizer: mvo`、`covariance.method` 可选 ewma。
- 新增风格暴露约束：`target.py` `_style_buckets` + `apply_style_cap`（size/momentum cap），`constraints.py` 加 `apply_style_cap`。alpha 强度加权 `alpha_strength_weights`（带 shrink）作为第三条路径。这是 V1"组合优化偏弱"的正面回应。

### B. 风格归因 + 容量 + NW 统计 ✅
- `quant/backtest/attribution.py` OLS：策略日超额 ~ market + size + value + momentum，返回 `alpha_ann_pct / betas / r_squared`。
- `quant/backtest/stats.py:9` `newey_west_sharpe`：Bartlett 核 NW 修正 Sharpe，`metrics.py:170` 接入并输出 `sharpe_nw`。
- `attribution.py:capacity_metrics`：成交参与率分布 + 建议最大 AUM；`metrics.py:184` 买卖换手分离 `turnover_buy_annual / turnover_sell_annual`。
- `report.py` 写入 `signal_mode`（strict/loose），loose 带乐观偏差警告；敏感性报告接入。

### E. 滑点 square-root ✅
- `quant/execution/slippage.py:29` `sqrt_law` 分支：`slip += k·(σ/100)·√participation`（Almgren-Chriss 风格），`k` 可配（默认 0.5）。`sim_rules.py` 加 `slippage_sqrt_k`。

### F. 上市日 PIT ✅
- `quant/data/listing.py`：优先 jbxx 真实上市日（`merge_jbxx_listing`），回退 daily 首条记录；落 `listing_dates.parquet`，universe 用 `trading_days_between(listing_date, as_of)`。解决了 V1"数据扩容静默改变 universe"问题。

### A. 部分 alpha 广度 ✅（量价类做得好）
- `quant/factors/library/flow.py:16` `flow_ratio_5` 有**量价代理回退**（近 5 日 vs 前 5 日成交额差 / 流通市值），PIT 快照缺失时仍可回测——设计诚实。
- `quant/factors/library/hot.py` 无快照时**返回 None**（不引入前视），实盘由 `update_daily` 落库。诚实。
- 多持有期 IC：`ic.py` `factor_ic_report(horizons=)` + `fit_weights --horizons 5,10,20` 混合 ICIR。

## 二、残留问题与名不副实（V2 新发现，按严重度排序）

### 🔴 R1. 基本面因子在历史回测中实际是"死的"——V1 的 A 项未真正闭合
`fundamental.py` 的 `ep_ttm / bp / roe / rev_yoy` **纯依赖 `bars.extras`（PIT 快照），无任何量价代理回退**（对比 `flow.py` 有 `_flow_proxy`）。而历史快照无法从 OHLCV 重建：

- `scripts/data/backfill_factor_snapshots.py` 把历史 `daily`（OHLCV：open/high/low/close/volume/amount）传给 `capture_fundamentals(d, day)`；
- `factor_capture.py:capture_fundamentals` 用列名匹配 `"市盈"/"市净"/"净资产收益率"` 提取 PE/PB/ROE——**OHLCV 根本没有这些列**，每个票 row 仅含 `{"code":...}` → `len(row)>1` 不成立 → 不写入 → 快照为空。

**后果链**：
1. 任何 pre-today 的回测/IC 拟合中，4 个基本面因子恒返回 None → 在 `compose_alpha` 被 `w<=0` 跳过 → **"20 因子"在回测里实际只有约 12 个量价因子在工作**。
2. walk-forward 权重拟合时，基本面因子 IC=0 → 权重=0 → 永远选不上，形成"永远死的"反馈环。
3. 更糟：`attribution.py:_style_factor_returns` 的 **value 因子**也读 `read_fundamentals_snapshot`，缺失时回退 `1/mv * 1e10`（市值倒数代理）——**历史归因里的 value beta 实际是 size 的镜像，不是真价值暴露**。即 V1 的 B 项"风格归因"在 value 维度上仍不可信。

**这是 V2 最实质的发现**：基本面 alpha 广度（V1-A）和 value 归因（V1-B）都未真正落地，只是代码存在。修复路径：从**季报披露日 point-in-time** 的财务数据 + 历史 PIT 市值重建 PE/PB/ROE 快照（AKShare 的 `stock_financial_*` + 披露日期对齐），或在基本面快照覆盖日期之前**显式禁用**这些因子与 value 归因，避免回测结论被静默高估。

### 🟠 R2. walk-forward IC 存在边界标签泄漏（OOS 不纯）
`fit_weights.py:42` `train_rows` = `sorted_dates[train_start_idx:i]`，即训练集最后一行是 `sorted_dates[i-1]`（td 的前一交易日）。但 IC 标签是该行的 **5 日前瞻收益**，跨度 `td .. td+4`——**这部分收益落在测试日 td 及之后**，等于训练时"偷看了"测试期开头 5 天的收益。

- 影响量级：504 日窗口里泄漏 5 天，aggregate 偏差小，但**系统性**地偏向"紧邻 td 前表现好"的因子，OOS Sharpe 被轻微高估。
- 修复：训练集丢弃最后 `horizon` 行（`train_start_idx : i - horizon`），或要求 `sd + horizon < td` 才入训练。当前未做。

### 🟠 R3. MVO 不是真正的约束优化器
`portfolio/mvo.py` 用解析解 `w = Σ⁻¹(μ/λ)` 再做 5 次"单票 cap + 归一化"投影：
- **行业/概念 cap、风格 cap 都在 MVO 之后外部施加**（`target.py:176` 之后），会破坏 MVO 的风险预算最优性——MVO 算出的最优在被 cap 砍切后不再是均值-方差最优。
- 无 equality 约束（满仓 `full_invest`）的严格处理、无换手约束、无最小权重下限逻辑。
- `μ` 直接用 alpha z-score，量纲上是启发式（z-score 当期望收益用），λ=2 无校准依据。

作为 v1 可接受，但离"机构级 MVO"（cvxpy 凸优化 + 行业/风格/换手/满仓联立约束）有距离。建议接 `cvxpy` 做真约束 QP，或在 cap 后至少做一轮再优化。

### 🟡 R4. EWMA 协方差冷启动偏差
`ewma.py:43` 递归 `cov = λ·cov + (1-λ)·x@xᵀ` 从 **0 起步**，前若干期协方差系统性偏低。RiskMetrics 标准做法是用更长历史样本协方差预热。当前无 warmup → 60 日窗口前期估值偏小 → 波动率目标可能轻微超配。影响中等。

### 🟡 R5. sqrt_law 滑点仍被全局上限压制
`slippage.py` 末尾 `min(slippage_max_pct, ...)`，默认 `slippage_max_pct=0.005`。高参与率下 sqrt 项可轻易超 0.5% 被截断 → **容量边界处低估冲击**（恰恰是容量分析最该准的地方）。且 `participation_rate` 仍默认 0.1（10% ADV）——对小资金偏松，与 R3 的容量曲线叠加会高估可承载 AUM。建议对 `sqrt_law` 放宽或取消 max，并按资金规模标定 participation_rate。

### 🟡 R6. `load_factor_weights` 的 `@lru_cache(maxsize=1)` 形同虚设
函数带 `as_of` 参数，`maxsize=1` 意味着 walk-forward 逐日调用不同 `as_of` 时每次都换出缓存、重读重解析 yml——无加速且无正确性问题；但若同一进程内既调 `as_of=None` 又调 `as_of=date`，缓存互相驱逐。建议改为 `functools.cache` 配合显式 key，或去掉装饰器。非正确性 bug，仅性能与卫生问题。

### 🟢 R7. 上市日仍有回退口径
`listing.py:build_listing_map_from_daily` 仍以 daily 首条记录为回退——若 jbxx 缓存未覆盖某票，退回 V1 原口径（数据可用日当上市日）。`merge_jbxx_listing` 已大幅缓解但未根除。建议接交易所 IPO 日期表彻底替换。

## 五、下一步优先级（按 ROI 排序）

1. **R1 基本面 PIT 数据源**：要么接季报披露日财务数据 + 历史 PIT 市值重建 PE/PB 快照，要么在覆盖前显式禁用基本面因子与 value 归因。**不做这步，因子广度和 value 归因都是纸面资产。**
2. **R2 walk-forward 边界去泄漏**：训练集丢弃末尾 `horizon` 行。一行级改动，纯收益。
3. **R3 MVO 升级为真约束 QP**：接 `cvxpy`，行/风格/换手/满仓联立；或在 cap 后再优化一轮。
4. **R5 sqrt_law 去上限压制 + participation_rate 按资金标定**：让容量曲线可信。
5. **R4 EWMA 加 sample-cov warmup**；**R6 去掉/修正 lru_cache**；**R7 上市日接交易所表**。

## 六、结论

修复方向正确、落地扎实度在个人系统中属上乘（尤其 D 项 OOS 闭环、G 项绩效口径、E 项 sqrt 滑点是实打实的进步）。但"全部落地、无遗留"不准确：**基本面因子在回测中失效（R1）是系统性硬伤**，直接拖累因子广度与 value 归因两项 V1 结论；walk-forward 边界泄漏（R2）与 MVO 非真约束优化器（R3）是次级残留。建议在宣称"可上资金"之前，先闭合 R1 与 R2——这两项决定了回测数字是否可信。
