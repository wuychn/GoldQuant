## 一、R8 / R9 / R10 核验结论

### R8. TTM 盈利 ✅ 真修复，构造正确

`quant/data/fundamental_pit.py`：
- `_decompose_quarterly_eps`：报告期累计 EPS → 单季 EPS。Q1=eps；Q2=eps−Q1cum；Q3=eps−H1cum；年报=eps−Q3cum。**累计字典按 (year, md) 键**，跨年不串味；prev 缺失时用比例启发（Q2→eps×0.5、Q3→eps/3）。
- `compute_ttm_eps`：`quarterly`（单季序列，按 report_date 升序）取**最近 4 个单季之和**；仅年报时直用年报；不足 4 季年化近似。
- `metrics_as_of`：先 `index.rows_as_of(code, as_of)` 取**所有公告日 ≤ as_of 的行**（PIT），再拆单季 → TTM → `pe_ttm = close / ttm_eps`、`ep_ttm = ttm_eps / close`。

**正确性核验**：
- TTM 用"最近 4 单季"跨年求和——2023Q4+2024Q1+Q2+Q3 这类跨年组合正确（每单季在各自年内用同年累计差分得到）。✅
- BPS 取最新报告期（**账面价值是存量而非流量，取最新是对的**，不应求和）。✅ 注释与实现一致。
- TTM 仅用 `announce_date ≤ as_of` 的行——PIT 闸门未破。✅
- 负 TTM（亏损）→ `return None` → 该票无 ep_ttm/bp，在 `compose_alpha` 被跳过——**标准处理**（PE 对负盈利无意义），但会从 value 信号中剔除约 10–20% 亏损股（见 R11）。

**结论**：V4 的 R8 闭合。value 因子不再有报告切换日阶跃，是干净的滚动 TTM 估值信号。

### R9. 公告日正则覆盖简称 ✅
`_parse_report_date_from_title` 规则表扩充：年度报告/半年度报告/第一/第三季度报告（全称）+ 年报/半年报/一季报/三季报（简称），并排除 摘要/取消/英文/提示性/更正/修订。简称缺失导致的法定截止日回退比例下降。✅

### R10. PitIndex 预排序 + bisect ✅
- `PitIndex.from_table` 一次构建 `code → [(pit_gate, row)]` 升序；`rows_as_of(code, as_of)` 用 `bisect.bisect_right` 定位，O(log n)。
- `panel_builder.py:111` 与 `attribution.py:39` 均**构建一次 index 复用**，传 `index=pit_index` 给 `metrics_as_of`。V4 的 O(码×日) 全表扫描已消除。✅

## 二、V5 新发现 / 残留（均为打磨级，非结构性）

### 🟢 R11. 亏损股被 value 因子剔除（可接受的口径选择，可改进）
`compute_ttm_eps` 在 `ttm <= 0` 时返回 None → 亏损公司无 ep_ttm/bp → value 因子截面仅含盈利股。这是行业惯例（PE 对负盈利无意义），但会**系统性把价值因子偏向盈利股**，且回测期间亏损→扭亏的票会在切换日因子值从 None 跳到正，引入截面成分变化。更稳的做法：直接用 `ep_ttm = ttm_eps / close`（带符号连续值），亏损为负 EP 自然排到弱价值端，不必丢弃。属口径优化，非 bug。

### 🟢 R12. 不足 4 季时的年化近似有季节性失真
`compute_ttm_eps` 对不足 4 季走 `sum(qs) * (4/len(qs))`——对季节性强的行业（H1/H2 利润分布不均）会失真。文档已自陈"近似"。仅影响次新股/新上市覆盖初期，量级小。

### 🟢 R13. 正则末条规则 `.*?(20\d{2})年报` 误命风险
规则表最后一条 `.*?(20\d{2})年报` 在极端标题（含多个年份+年报字样）可能捕获错误年份，但前序全称/简称规则已先匹配，实战命中概率低。建议置于此规则之前用 `^` 锚定或删除。低优先级。

### 🟢 R7. 上市日回退（维持，低优先级）
`listing.py` 仍以 daily 首条记录为 jbxx 缺失时回退。未处理，影响次新股过滤精度。

## 六、结论

本轮把 V4 的最后一项因子质量残留 R8 彻底闭合：value 因子现在是**公告日 PIT + 单季差分 + 滚动 4Q TTM** 的干净估值信号，BPS 取最新报告期（存量口径正确），辅以 R9 正则扩简称、R10 PitIndex 性能优化。V2 至 V4 累计的结构性硬伤——基本面死因子 / 报告期前视 / 多期限泄漏 / 非 TTM——**全部清零**。剩余 R11/R12/R13/R7 均为口径打磨与边界优化，不影响回测可信度。

**阶段判定**：GoldQuant 已从"接近机构级研究闭环"进入"**可上小资金纸面/实盘验证**"阶段。当前代码层面的研究闭环（PIT 数据 → TTM 因子 → IC/FDR 选权 → walk-forward OOS → SLSQP 约束 MVO → strict 回测 + 风格归因 + 容量/敏感性）已完整且扎实。下一步重心应从"改代码"转向"**跑数据验证**"：建议执行 `build_fundamental_pit --resume` + `backfill_factor_snapshots` + `fit_weights --walk-forward` + `backtest.run --sensitivity`，用真实 OOS 区间绩效（尤其 NW-Sharpe、value 因子 IC、容量曲线）来证伪或证实当前设计——这才是从"代码可信"迈向"策略可信"的关键一步。
