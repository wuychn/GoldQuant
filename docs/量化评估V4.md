# GoldQuant 系统评估 V4（顶级量化视角·四评）

> 评估日期：2026-07-29
> 评估方式：直接核验工作树未提交修改 + 新文件，对照 V3 的 R1' / R2'。
> 结论先行：**R1' 与 R2' 真修复且实现扎实**——基本面 PIT 闸门已改为"公告日 ≤ as_of"，缺失时回退**法定披露截止日（保守、绝不前视）**；walk-forward 多期限泄漏按 `max(horizons)` 切片闭合。**前视防护这一系统性硬伤至此全部清零**。R1' 闭合后，暴露出一个不同类别的新残留：基本面因子用的是报告期 eps/bps 而非 TTM，使 PE/PB 在报告边界跳变、不是干净的 value 信号。

## 一、R1' / R2' 核验结论

### R1'. 公告日闸门 ✅ 真修复，实现扎实

**闸门已正确闭合**（`quant/data/fundamental_pit.py`）：
- 列扩展为 `code, report_date, announce_date, roe, eps, bps, rev_yoy`。
- `effective_announce_date(row)`：有真实公告日则用，否则回退 `regulatory_disclosure_deadline`（Q1→04-30、H1→08-31、Q3→10-31、年报→次年 04-30）。
- `_latest_pit_row` 的 PIT 闸门是 `effective_announce_date(row) <= as_of`，并按闸门日排序取最近——**彻底替代 V3 的 `report_date <= as_of`**。
- `metrics_as_of` 注释明确改为 "announce_date <= as_of 闸门"。

**数据来源与回退都安全**：
- `fetch_announce_map_for_code` 走 AKShare 巨潮 `stock_zh_a_disclosure_report_cninfo`（定期报告），按标题正则解析报告期、取每个报告期最早公告日。
- `fetch_financial_pit_for_code` 每行写 `announce_date = amap.get(rd) or regulatory_disclosure_deadline(rd)`——**缺失即用法定截止日**。
- **法定截止日回退是真正的保守 PIT**：实际公告日 ≤ 法定截止日，故用截止日当闸门只会"略晚用"，绝不会前视。V3 担心的"年报次年 01-01 即用"前视已消除（年报现以次年 04-30 为最晚闸门，真实公告更早）。
- `write_fundamental_pit` / `read_fundamental_pit_table` 对旧 parquet（无 announce_date 列）自动回填法定截止日，向后兼容。

**运营项同步落地**（V3 提的运营项）：`build_fundamental_pit` 加 `--resume`（跳过已有 code）/`--batch-size`/`--sleep`/`--retries` + 指数退避重试 + 分批写入。✅

**结论**：V3 的核心硬伤 R1' 已正确闭合。基本面因子现在是 PIT-clean 的，value 归因同理。

### R2'. 多期限 IC 标签泄漏 ✅ 真修复
- `fit_weights.py:52` `label_horizon = max(horizons) if horizons else horizon`，`:58` `train_end_idx = i - label_horizon`。
- 训练切片末行 index = `i - max(horizons) - 1`，其最长（20 日）前瞻标签结束于 `i - 1 < td`——**10/20 日 IC 不再泄漏进测试期**。一行级改动，干净闭合。✅

## 二、V4 新发现（R1' 闭合后暴露，不同类别）

### 🟠 R8. 基本面因子用报告期 eps/bps，非 TTM——value 因子噪声大

R1' 解决了"前视"，但因子**构造口径**仍有问题：

- `fetch_financial_pit_for_code` 从 `stock_financial_analysis_indicator_em` 取 eps/bps，这是**报告期累计值**（Q1=一季度累计、H1=半年累计、年报=全年），**不是滚动 12 个月 TTM**。
- `metrics_as_of` 算 `pe_ttm = close / eps`、`ep_ttm = eps / close`、`pb = close / bps`、`bp = bps / close`。
- 后果：每次最新 PIT 报告切换，eps 在"Q1 累计 → H1 累计 → Q3 累计 → 年报"间跳变，PE 随之阶跃（Q1 之后 PE ≈ price/Q1_eps 偏高 4 倍量级，半年报后偏高 2 倍）。因子名是 `ep_ttm`/`bp`，**实际既非 TTM 也不跨报告期可比**。
- 影响：value 因子（ep_ttm/bp）在报告切换日截面出现人为跳变，IC 被报告期切换噪声污染，**不是干净的估值信号**。这不影响 PIT 正确性，但削弱因子质量。

**修复路径**：构造 TTM 盈利（最近 4 个季度 eps 之和）/ TTM 净资产（或用最新 bps 但需口径一致），再算 `pe_ttm = close / ttm_eps`。需要 `fundamental_pit` 保留多季度数据并在 `metrics_as_of` 滚动求和——当前只取"最近一行"，无 TTM 滚动逻辑。

### 🟢 R9. 公告日来源覆盖不全（保守回退兜底，安全但非最优）
- 标题正则只匹配"年度报告/半年度报告/第一季度报告/第三季度报告"，未覆盖"年报/半年报/一季报/三季报"等简称 → 部分公告日缺失 → 回退法定截止日（保守、安全）。
- 巨潮 API 对部分代码限流/失败时同样回退法定截止日。**无前视风险**，但 value 因子在缺失码上会"晚用到截止日"，IC 略有滞后偏差。建议扩充正则 + 失败码重试补抓。

### 🟢 R10. 性能（非正确性）
- `panel_builder` 对每个 `(code, as_of)` 调 `metrics_as_of` → `_latest_pit_row` 在全表上做 `df[code==code]` 过滤与 `apply(effective_announce_date)`。O(码数 × 评估日数) 全表扫描，离线可接受但全历史面板会慢。建议预构建 `{code: 按 announce_date 排序的行列表}` 一次、`bisect` 定位。

## 六、结论

本轮把 V3 的两项硬伤彻底闭合：R1' 公告日闸门（真实公告日优先、法定截止日保守回退）消除了 ~30–120 天的基本面前视；R2' `max(horizons)` 切片消除了多期限 IC 泄漏。**前视防护从 A- 升 A、OOS 闭环从 A- 升 A、风险归因从 C+ 升 B——至此回测已基本可信。** R1' 闭合后暴露的 R8（非 TTM eps/bps）是新的、不同类别的残留：它不影响 PIT 正确性，但让 value 因子在报告切换日跳变、不是干净的估值信号。这是当前唯一影响因子质量的待办，做完 value 因子即真正落地。总体上，GoldQuant 已从"工程纪律良好的辅助系统"演进到**接近机构级研究闭环**的 A 股选股平台，余下的是因子质量打磨而非结构性缺陷。
