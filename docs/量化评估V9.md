## 二、V8 之外的正向修复（本批额外带出）

### 🟢 A1. MVO 分支真传集中度/风格约束（正确性修复）

`target.py:target_weights` 的 MVO 分支此前只传 `max_weight`，**绕过 sector/concept/style cap**。现补 `sectors/sector_cap/concepts/concept_cap/style_buckets/style_caps`（见 git diff）。即"实盘 optimizer=mvo"现在真受集中度约束——这是 V8 没点名但比 R21 更要紧的正确性 bug。✅

### 🟢 A2. walk-forward 防 IC 标签泄漏（前视修复）

`fit_weights.py:fit_walk_forward_weights` 加 `label_horizon = max(horizons)`，训练窗右端从 `i-1` 改为 `i-label_horizon`，丢弃最长前瞻档避免 10/20 日 IC 标签泄漏进训练（`test_walk_forward_train_excludes_max_horizon`）。V8 只查了回测侧 `load_factor_weights(as_of=d)` 的 OOS，**权重拟合侧的标签泄漏**是 V8 漏的，本批补上。✅

### 🟢 A3. 风格归因 + 容量曲线（超出 V8 要求）

`backtest/attribution.py` 新增 `style_attribution`（策略日收益对 market/size/value/momentum 因子回归）+ `capacity_metrics`，接进 `compute_metrics`。V8 R26 只要基准超额，这里多做了一层因子归因——机构标配。✅

### 🟢 A4. 23 项测试覆盖全部修复

`test_eval_fixes.py` 23 个 `test_*` 覆盖 NW-Sharpe / MVO / sqrt-law 滑点 / capacity / fundamental_pit / TTM EPS / 披露季轮转 / speed 代理 / 因子相关 / 基准超额 / α 未校准标注 / walk-forward 标签隔离。**每一项修复都配了测试**——这是工程纪律到位的硬证据。

## 三、R24 与 R25 的剩余开口（需明说）

### R24-补：speed 代理在日频下退化为与 intraday_strength 共线

`spot_row_from_daily` 的 `speed = (close-open)/open*100`，而 `intraday_strength = (last-open)/open`，日频代理里 `last==close`，**二者数值同源**。即代理回测中 `speed` 与 `intraday_strength` 完全共线，不携带额外信息。

- **后果**：盘中 5 因子回测在代理下实际只有 4 个独立信号；`speed` 的独立 IC 测不出。
- **诚实度**：`spot_row_from_daily` docstring 已自述"与 live `spot_em.speed` 同向但不等价"——作者知道，但未点破"共线退化"。
- **修复方向**：要么接真实分时/快照历史重放（与 R25 同一动作）；要么把 speed 代理换成与 intraday_strength 正交的量，如日内振幅内的高位占比 `(high-max(open,close))/(high-low)` 或午盘相对早盘的成交额分布——需历史分时，日 K 不够。

### R25：端到端镜像实盘回测仍未建（最大开口项）

当前两条回测都不是实盘路径：
- `scripts/backtest/run.py`：日频 alpha → TargetPortfolio → **T 开盘一次性撮合**。
- `scripts/backtest/run_intraday_timing.py`：盘中 θ 择时 **edge 探针**，无组合权益/滑点/T+1。

实盘是：日频 alpha top-N 作战池 → **T+1 盘中** `compose_intraday_alpha` α_z≥θ 触发 → **最新价分档买入**。**没有任何一条回测复刻此路径**。因此即便 R26 补全了基准指标与 NW-Sharpe，跑出来的 Sharpe 仍只反映"日频开盘口径"，不反映实盘。

这一项不闭合，"回测可信"就始终带星号。

## 六、下一步优先级

1. **🔴 跑一次真实端到端回测（最高 ROI，三评不变）**：
   `python -m scripts.data.build_daily` → `python -m scripts.data.build_fundamental_pit` → `python -m scripts.factors.fit_weights --walk-forward --fdr-alpha 0.05` → `python -m scripts.backtest.run --start 2022-01-01 --end 2025-12-31 --sensitivity`。
   现在 R26/A3 让这次回测能产出**超额 Sharpe(NW)、IR、beta、风格归因、容量曲线**——值得看一眼了。看四件事：超额是否为正且 NW 显著、value/各因子真实 ICIR、换手与容量、权重是否真激活（解 R23）。

3. **R24-补 speed 代理正交化**：或承认盘中层只能等真实分时数据。
4. **§四 P1 补 4 个风险/行为因子**（MAX_20/ivol_60/amihud_20/beta_60）：纯日线、A 股预期 IC 显著，前置 R17 已通。
5. **R27 正交加权**（可选）：诊断已让共线可见，是否上残差正交看一次 IC 报告的 high_pairs 再定。

## 七、结论

V8 的十项发现本批闭合七项、部分修两项、未修一项（R25）。同时顺手修了三项 V8 没点到但更紧的正确性/前视问题（MVO 真约束、walk-forward 标签泄漏、风格归因），并为每项修复配了测试。**代码层已达"可证伪"的全部前置条件**——基准指标、NW-Sharpe、风格归因、容量曲线、OOS 权重隔离都备齐了。

但 V8 的两大核心判据**一字未动**：
- **R25 端到端镜像实盘回测仍未建**——跑出来的 Sharpe 仍只反映日频开盘口径，不反映实盘。
- **"验证状态=零"仍为零**——九轮评估、约 25 项修复，全部静态核验，真实 OOS 绩效始终未产出。

**最高 ROI 的下一步不是第十轮代码审计，而是把真实数据灌进去跑一次。** 那一眼会同时：证伪/证实前九轮修补、暴露 R25 缺口到底多大、指出 §四的因子缺口里哪个最值得补。在那一眼出现之前，"对标顶级量化"仍只是断言。
