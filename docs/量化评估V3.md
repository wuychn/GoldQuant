# GoldQuant 系统评估 V3（顶级量化视角·三评）

> 评估日期：2026-07-29
> 评估方式：直接核验工作树未提交修改 + 新文件（`fundamental_pit.py` / `build_fundamental_pit.py` 等），逐一对照 V2 的 R1–R6。
> 结论先行：**R2/R3/R4/R5/R6 真修复且实现到位；R1 部分修复但引入了新的前视**——基本面 PIT 闸门用"报告期"而非"公告日"，代码注释还把它误标为"保守 PIT"，实际是乐观前视。这是 V3 的核心发现。

---

## 一、R1–R6 核验结论

### R1. 基本面因子 ⚠️ 部分修复（数据活了，但 PIT 闸门错——新前视）

**已修好的部分**：
- 新增 `quant/data/fundamental_pit.py`：季报财务表 `store/fundamental_pit/part.parquet`（code/report_date/roe/eps/bps/rev_yoy），`metrics_as_of` 按 as_of 取最近已披露行 + 当日 close 算 PE=close/eps、PB=close/bps。基本面因子**不再是死因子**——历史回测有了数据。✅
- `panel_builder.py` 在 d 循环内 `bars.extras = dict(pit_extras)` 置于 `f.compute` **之前**，且每 d 重新设置，无跨日污染。✅
- `attribution.py` 删掉了 `1.0/mv*1e10` 伪代理，无 ep 时 `continue` 跳过而非用市值倒数冒充。✅ value 归因不再骗人。

**新前视（V3 核心发现）**：
`fundamental_pit.py` 用 `report_date <= as_of` 作为 PIT 闸门，**没有公告日列**。代码注释自述："仅使用 report_date <= as_of 的最新一行（保守 PIT；未用公告日则略偏早可用）"——**这个判断是错的，方向相反**：

- A 股季报披露窗口：Q1(03-31) 公告截止 04-30、半年报(06-30) 截止 08-31、Q3(09-30) 截止 10-31、年报(12-31) 次年 04-30。
- 用 report_date 当闸门，意味着 as_of = 报告期+1 天就"可用"该报告——但实际要等 30 天（季报）到 **120 天（年报）**后才公告。
- **年报最严重**：report_date=12-31，代码从次年 01-01 起就用该年报数据，而真实公告要等 04-30 → **~4 个月前视**。

这正是 V2 R1 担心的"基本面 PIT 数据源"问题的残留：数据接进来了（因子活了），但**闸门用错日期**，把"未公开"的财报当"已公开"用，系统性高估 ep_ttm/bp/roe/rev_yoy 的 IC——尤其在每个报告披露窗口前后。`fetch_financial_pit_for_code` 走 AKShare `stock_financial_analysis_indicator_em` 只返回报告期，无公告日，所以**当前管线根本拿不到公告日**，必须换数据源（如 `stock_report_disclosure` 公告日表 / 巨潮实际公告日）并以公告日作为 `report_date <= as_of` 的闸门，才能真正 PIT。

**结论**：R1 从"死因子"升级为"活但带前视"——比 V2 好，但仍不可信。value 归因同理继承了报告期闸门前视。

### R2. walk-forward 边界标签泄漏 ✅ 主体已修，多期限残留
- `fit_weights.py:57` `train_end_idx = i - horizon`，训练切片 `sorted_dates[train_start_idx : i-horizon]`，最后一行 index = i-horizon-1，其 5 日前瞻收益结束于 i-1 < td。**主持有期 horizon=5 的泄漏已消除**。✅
- **残留**：`factor_ic_report(..., horizons=(5,10,20))` 在同一份 `train_rows` 上还算了 10/20 日 IC 供多期限 ICIR 混合。20 日前瞻标签的末行结束于 `(i-horizon-1)+20 = i+14 > td`——**长期限 IC 仍泄漏进测试期**。切片应按 `max(horizons)=20` 而非主 `horizon=5`。属轻度残留。

### R3. MVO 升级为真约束优化器 ✅
- `portfolio/mvo.py` 改用 `scipy.optimize.minimize(method="SLSQP")`：目标 `max μ'w − (λ/2)w'Σw`，联立等式约束 `Σw=full_invest` + 不等式 cap（单票 bound、行业、概念、风格），`maxiter=200, ftol=1e-9`；无 scipy 才回退解析解+投影。
- `target.py:179` 把 `sectors/sector_cap/concepts/concept_cap/style_buckets/style_caps` 全部传入。约束**在优化器内部**施加，不再外部砍切破坏最优。✅ 真改进。
- 仍存（可接受）：μ 直接用 alpha z-score（量纲启发式）、λ=2 无校准依据——属设计选择，非 bug。

### R4. EWMA 冷启动 ✅
- `ewma.py` 加 `warmup = min(max(20, n+5), t)`，用 `np.cov(R[:warmup].T)` 预热后再从 `warmup` 起递归 `cov = λ·cov + (1−λ)·x@xᵀ`。冷启动偏低已修。✅

### R5. sqrt_law 滑点上限 ✅
- `sim_rules.py` 加 `slippage_sqrt_max_pct=0.02`（独立于固定档 0.5% 上限）；`slippage.py` 对 `sqrt_law` 用 `min(slippage_sqrt_max_pct, ...)`。高参与率冲击不再被 0.5% 截断。✅ `participation_rate` 仍 0.1（未按资金标定，但非 bug）。

### R6. lru_cache ✅
- `config.py` 移除 `@lru_cache(maxsize=1)`，注释说明"as_of 逐日变化，缓存 key 无效"。✅

## 三、V3 新发现 / 残留（按严重度）

### 🔴 R1'. 基本面 PIT 闸门用报告期而非公告日（~30–120 天前视，年报最重）
详见上文 R1。这是 V3 唯一的硬伤。**修复路径**：换带公告日的数据源（AKShare `stock_report_disclosure` 或巨潮公告日），把闸门从 `report_date <= as_of` 改为 `announce_date <= as_of`。在闭合前，基本面因子 IC 与 value 归因均不可信，回测结论仍被乐观高估。

### 🟠 R2'. 多期限 IC 标签泄漏
`fit_weights` 切片按主 `horizon=5`，但 `horizons=(5,10,20)` 的 10/20 日前瞻标签越过 td。修复：切片改用 `i - max(horizons)`。一行级改动。

### 🟢 R7. 上市日回退口径未动（维持 V2）
`listing.py` 仍以 daily 首条记录为 jbxx 缺失时回退。未在本轮处理，低优先级。

### 🟢 运营项
- `build_fundamental_pit` 对 universe 全量逐只调 AKShare，无显式限流/重试/断点续跑——拉全市场会慢且易失败。建议加分批/缓存/重试。
- `fetch_financial_pit_for_code` 用 `start_year="2018"`，2018 年前无基本面数据——回测若跨更早区间需注意。

## 六、结论

本轮修复质量高：R3（SLSQP 真约束 MVO）、R4（EWMA warmup）、R5（sqrt 独立上限）、R6（去 lru_cache）、R2 主期限泄漏——都是实打实的工程进步，组合优化从 C+ 升 B、OOS 闭环从 B+ 升 A-。但 **R1 出现了"修旧引新"**：基本面因子从"死的"变成"活但带报告期前视，且代码注释把它误判为"保守 PIT"——实际是 ~30–120 天的乐观前视，年报最重。在公告日闸门闭合之前，基本面 alpha 与 value 归因仍不可信。**只剩 R1' 一项硬伤 + R2' 一行级残留**，离"可上资金的干净回测"已非常接近。
